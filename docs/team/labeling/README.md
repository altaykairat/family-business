# Разметка эталона DEV (ground truth v0)

> Решение 22 ([discussion.md, «Обсуждение 4»](../discussion.md#обсуждение-4-свой-эталон-и-симуляция-цикла)): весь DEV (65 диалогов) размечает Алтай вместе с новым чатом-помощником. Эта разметка — эталон `dev-gold@v1` для метрик, апелляций и симуляции цикла обучения, пока нет другой. Решение по каждой метке — за Алтаем.

| Файл | Что это |

## Порядок

1. **Новый чат.** Без доступа к репозиторию и без наших прогонов: не показывай ему ответы моделей из `runs/` — иначе эталон повторит их ошибки. Желательно модель **другого семейства**, чем та, что пойдёт в финальный пайплайн (если финал — Claude, размечай с ChatGPT или Gemini, и наоборот): так меньше общих слепых пятен, и точность не завышается.
2. Вставь [assistant-prompt.md](assistant-prompt.md) целиком (всё ниже линии). Проверь пересказ критериев.
3. По одной вставляй порции из `batches/` по порядку. Русские идут первыми — на них складывается большая часть правил.
4. Просматривай таблицу и спорные места, отвечай правками или «ок». Спорную трактовку решай один раз и фиксируй: «Правило: …».
5. Пиши «CSV» → сохрани блок в `labels/batch-NN.csv` (с заголовком).
6. После последней порции — «Свод» → перенеси правила в [rulebook.md](rulebook.md).

Если чат начал «плыть» (забывает правила, путает номера реплик) — открой новый, вставь промпт и текущий свод правил, продолжай со следующей порции.

## Импорт в платформу

```bash
python3 - <<'EOF'
import csv, glob
rows = [r for f in sorted(glob.glob("docs/team/labeling/labels/batch-*.csv")) for r in csv.DictReader(open(f, encoding="utf-8"))]
with open("docs/team/labeling/labels/all.csv", "w", newline="", encoding="utf-8") as out:
    w = csv.DictWriter(out, fieldnames=["conversation_id", "criterion_id", "answer", "evidence_idx", "comment", "annotator"])
    w.writeheader(); w.writerows(rows)
print(len(rows), "меток,", len({r["conversation_id"] for r in rows}), "диалогов")
EOF
```

```bash
python3 -m cqa gt.import path=docs/team/labeling/labels/all.csv set=dev-gold reason="v0: Алтай + чат-помощник, весь DEV" actor=r-01
```

Платформа сама разобьёт эталон на часть для настройки и отложенную часть (40%, по языку и каналу) и запишет версию в историю. Правка меток позже — `gt.update`, каждая правка — новая версия.

Ожидается 520 строк (65 × 8). Можно импортировать и частично (`allow_partial=true`) после первых порций, чтобы сразу смотреть метрики.

## Что делаем с эталоном потом

1. **Исходная точность:** `metrics.compare` против уже сделанных прогонов (`sa_v1` и др.) — точность по критериям, «Нет» ↔ N/A, ошибка итога.
2. **Симуляция цикла:** на части для настройки расхождения модели с эталоном становятся апелляциями, решение проверяющего берётся из эталона → анализ → предложения → новая версия промпта → повторный прогон → «до и после» на отложенной части.
3. **Тест адаптивности:** второй вариант эталона с перевёрнутыми спорными трактовками (S4, S7, S9, …) — система должна сойтись и к нему.

## Результат разметки (2026-11-07)

- **Готово:** 65 диалогов, 520 меток — [labels/all.csv](labels/all.csv), [labels/all.json](labels/all.json) (вход `gt.import`), [labels/results.json](labels/results.json) (тот же эталон в формате организаторов), разбор — [labels/REVIEW.md](labels/REVIEW.md). Помощник — GPT-6 (Codex), решения — Алтай. Правила R1–R8 — в [rulebook.md](rulebook.md).
- **Проверка (сессия дизайна):** все 8 критериев в каждом диалоге, допустимые ответы, N/A только где разрешён, у каждой метки есть доказательства и причина, все номера реплик существуют в транскрипте, итоги в `results.json` совпадают с `cqa/scoring.py` до сотых.
- **Распределение (основной вариант):** c01 да 60 / нет 5; c02 N/A 40; c03 N/A 55; c04 = 20 в 52; c05 нет 19; c06 = 10 в 52; c07 да 34 / нет 23 / N/A 8 (в строгом: да 2 / нет 55); c08 да 9. Средний итог 82.28 (строгий — 78.8).
- **c07 — решено: основной эталон буквальный** (чек-лист: «подвёл итог **или** предложил дальнейшую помощь и попрощался»). Строгое правило R4 сменило 34 метки ([labels/C07_STRICT_REVISION.md](labels/C07_STRICT_REVISION.md)) и сохранено как альтернативный эталон для теста адаптивности: `labels/all_strict.*`, `labels/results_strict.json`.
- **В платформе:** `dev-gold@v1` — основной, `dev-gold-strict@v1` — альтернативный; разбиение 39 на настройку / 26 отложено.

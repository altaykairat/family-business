# JSON эталона

- `all.json`: внутренний формат `checklist/items/labels`, совместимый с JSON-входом `gt.import`. Эквивалент `all.csv`; импорт не выполнялся.
- `results.json`: тот же эталон в структуре приложения организаторов JSON 1.0: 65 записей, по 8 критериев, обоснования, исходные номера реплик и программно рассчитанные баллы. N/A преобразован в null, бинарные ответы — в boolean, шкалы — в числа. Грубое нарушение не обнуляет итог.
- CSV сохранён. При изменении меток JSON нужно пересоздать: `python3 scripts/export_labeling_json.py` из корня репозитория.

## Происхождение и отличие от сдачи

Это экспертный эталон с помощью Codex, а не результаты автоматического прогона системы. Поэтому он находится рядом с разметкой, а не в `results/dev/results.json`. PROD не создавался. Commit/push не выполнялись.

`team_name=altay+chat` — обозначение авторов этой разметки из исходного CSV, а не подтверждённое название команды для сдачи. `model.name=GPT-6 (Codex); expert review: altay` отражает помощника и экспертную проверку, `mode=external_api` — удалённую модель, не локальный запуск. Перед использованием как файла сдачи необходимо указать фактическое имя команды и модель соответствующего прогона. Параметры экспортёра: `--team-name` и `--model-name`.

**Основной вариант — буквальный c07** (итог или помощь + прощание, как в чек-листе). Строгая трактовка R4 сохранена отдельно: `all_strict.csv`, `all_strict.json`, `results_strict.json` — альтернативный эталон для теста адаптивности. Пересоздать строгий JSON: `python3 scripts/export_labeling_json.py --csv docs/team/labeling/labels/all_strict.csv` с выводом в отдельную папку, затем переименовать.

Проверены: точное совпадение 65 ID с исходными DEV JSON, уникальность 8 критериев, допустимые типы и значения, наличие обоснований, принадлежность всех доказательств исходному транскрипту, полярность critical_flag, расчёт баллов с N/A и повторное чтение JSON.

# Freedom Quality — CQA (Conversation Quality Analytics)

Платформа контроля качества диалогов контакт-центра Freedom Broker, сделанная на хакатоне CQA командой **family-business**. Она оценивает работу оператора в чатах (RU / KZ / EN) и звонках по редактируемому чек-листу:
- ответ по каждому критерию с объяснением и дословными цитатами-доказательствами;
- баллы с перераспределением весов при N/A и отдельным флагом грубой ошибки;
- апелляции оператора и окончательные решения проверяющих;
- цикл обучения: система учится на решениях проверяющих.

**Главное правило системы — правда только от человека.** LLM готовит черновую оценку и доказательства, баллы считает код, а решения, правила, веса и версии чек-листа меняет только человек.

## Результаты

На нашем эталоне — ручной разметке всех 65 диалогов DEV ([docs/team/labeling/](docs/team/labeling/README.md)). Это приближение к эталону организаторов, поэтому честнее всего сравнивать варианты между собой.

| | Совпадение меток | Ошибка итога (MAE) | Итог в пределах ±5 |
|---|---|---|---|
| R-base: шаблон v2, все 65 диалогов DEV | 84,4% | 10,6 | 16 / 65 |
| До цикла обучения: 26 отложенных диалогов | 84,6% | 11,5 | 31% |
| **После двух итераций цикла: те же 26** | **88,0%** | **9,6** | **54%** |

- **Доказательства:** 879 ссылок на реплики — 100% существующих, 100% дословных цитат.
- **Грубые ошибки:** найдено 8 из 9, ложных срабатываний нет.
- **Цикл обучения:** исправлено 10 меток, сломано 3. Выборка маленькая (p = 0,09), но направление ясное. Первая итерация нашла слишком широкое правило, человек его сузил, вторая подтвердила улучшение. Подробно — [docs/team/experiments.md](docs/team/experiments.md).
- **Почему такая архитектура.** Сильная модель важнее дробления на подзадачи: один вызов на диалог (V1) не хуже 4 вызовов по секциям и 8 по критериям, а стоит в 2–3 раза меньше. Баллы, посчитанные моделью, ошибались на 11–14 пунктов, поэтому их считает код.

## Как это работает

```
диалог ──► промпт из активной версии чек-листа (+ уточнения правил и прецеденты)
      ──► ChatGPT · Codex: новая сессия без контекста (пустая папка, только чтение, без чужих инструкций)
      ──► проверка ответа: схема, допустимые ответы, существование реплик, дословность цитат
      ──► баллы считает код: веса, перераспределение N/A, округление, флаг грубой ошибки отдельно
      ──► карточка: ответ, объяснение, цитаты, уверенность, «Откуда ответ»
      ──► апелляция оператора ──► решение проверяющего (тип A–D, окончательное) ──► итог пересчитывается поверх
      ──► цикл обучения: закономерности ──► предложения оркестратора ──► человек принимает ──► регрессия ──► активация
```

## Возможности

- **Роли:** администратор, руководитель, проверяющий, оператор. Права проверяет сервер.
- **Диалоги и карточка оценки:**
  - фильтры по языку, каналу, грубым ошибкам и апелляциям;
  - ответ по каждому критерию с цитатами, клик по номеру — переход к реплике;
  - решения проверяющих в виде «было → стало».
- **Апелляции:** оператор оспаривает критерий со ссылкой на реплику. Проверяющий подтверждает или меняет ответ, указывает тип A–D и причину. Исходная оценка не меняется, итог пересчитывается поверх. Решение можно сделать прецедентом для промпта.
- **Чек-лист под полным контролем:**
  - можно добавлять и менять критерии, веса, условия N/A и ступени шкал;
  - каждое сохранение — новая неизменяемая версия, удалённое уходит в архив;
  - активирует человек, оценки пересчитываются без вызова модели;
  - если новому критерию нужен ответ модели, система сообщает, где именно.
- **Цикл обучения:**
  - закономерности «критерий × было → стало × ситуация» с уверенностью: случаи, разные проверяющие, противоречия;
  - ниже порога «копится» — одно решение систему не меняет;
  - оркестратор предлагает уточнения правил, администратор принимает;
  - регрессия на отложенных диалогах, затем «До и после».
- **Точность:** сравнение любого прогона с эталоном по каждому критерию, с доверительными интервалами и списком расхождений.
- **Очередь проверки:** ответы, где модель сама сомневается (нехватка данных, неоднозначность, низкая уверенность), и апелляции, ждущие решения.
- **Оценка и сдача:**
  - загрузка набора по `group_id` из API организаторов или из JSON;
  - оценка всего набора в фоне с прогрессом;
  - выгрузка `results/dev` или `results/prod` с проверкой формата.
- **Прозрачность и аудит:**
  - журнал событий только с добавлением и цепочкой хешей (`history.verify`);
  - «машина времени» — параметр `until` у любой команды чтения;
  - по любой оценке видны промпт, сырой ответ модели, все версии и действия людей.
- **API для фронтенда и Dynamics 365:** 104 команды. `GET /api/v1/commands` описывает их все. Без cookies, с CORS, все id — строки.

## Быстрый старт

Нужен Python 3.9+, сторонних зависимостей нет.

```bash
python3 -m cqa serve          # интерфейс: http://127.0.0.1:8765 · API: http://127.0.0.1:8765/api/v1/commands
```

- **Оценка моделью.** Используется Codex CLI из приложения ChatGPT — путь задан в [config/providers.json](config/providers.json), вход в ChatGPT должен быть выполнен. Без него работает режим «Вручную»: промпт копируется в любой чат модели, ответ вставляется обратно.
- **Данные организаторов.** Нужен `.env` с `CQA_API_URL`, образец — [.env.example](.env.example). Загрузка — в разделе «Оценка и сдача» или командой `python3 scripts/fetch_dataset.py DEV`.
- **Роль** выбирается внизу бокового меню.

**Контрольный набор за пять шагов:**
1. «Оценка и сдача» → `group_id` → «Загрузить из API».
2. Выбрать набор → «Оценить в фоне» с выгрузкой в `results/prod`.
3. Дождаться статуса «готово» и проверки «пройдена».
4. `git commit`.
5. `git push`.

**Из командной строки** — любая команда API: `python3 -m cqa <команда> ключ=значение`. Фоновое задание `job.evaluate` живёт в процессе сервера, поэтому из командной строки используйте шаги ниже.

```bash
python3 -m cqa run.prepare run_id=r-x dataset=fbroker template=v2 agents=codex-cli   # промпты по активному чек-листу
python3 -m cqa run.dispatch run_id=r-x agent=codex-cli provider=codex-cli          # каждый промпт — новая сессия Codex
python3 -m cqa run.ingest run_id=r-x && python3 -m cqa eval.import source=r-x:codex-cli
python3 -m cqa metrics.compare gold=dev-gold@v1 sources=r-base:codex-cli
python3 -m cqa results.check path=results/prod/results.json set=prod expected=10
python3 -m cqa history.verify
python3 -m unittest discover -s tests                              # 66 тестов
```

## Структура репозитория

```
cqa/                 платформа: пайплайн (prompts, responses, scoring, run), история и состояние (events, state, db),
                     версии, апелляции, эталон и метрики, цикл (loop, tasks, simulation), провайдеры LLM, фоновые
                     задания, выгрузка results, API и HTTP-сервер
web/                 интерфейс (index.html, app.js, platform.js, style.css) — раздаётся `python3 -m cqa serve`
prompts/templates/   шаблоны промптов (v2 — текущий)
config/              параметры пайплайна и платформы, провайдеры LLM, цены, шаблоны задач оркестратора
data/                чек-листы (v1 — организаторов, v2–v8 — наши), наборы dev / fbroker / swap, эталон
runs/                прогоны: промпты, ответы моделей, проверки (r-base, r-loop, r-loop2, r-prod и эксперименты)
results/             файлы сдачи для организаторов
history/             журнал событий, блобы, задачи оркестратора, отчёты метрик и регрессий
variants/            альтернативные прототипы пайплайна (Codex, Antigravity)
tests/               тесты
```

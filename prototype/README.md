# Transparent CQA Lab

Экспериментальный прототип в отдельной ветке. Он использует [официальную текстовую копию задания](../docs/task.md), [текстовую копию чек-листа](../docs/checklist.md) и [машиночитаемый чек-лист](../data/checklists/default.json) из общего репозитория. Исходные PDF в этой ветке отсутствуют; перед защитой стоит сверить копии с ними.

## Запуск

Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r prototype\requirements.txt
Copy-Item prototype\.env.example .env
.\.venv\Scripts\python.exe -m uvicorn server:app --app-dir prototype --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. На macOS/Linux используйте `source .venv/bin/activate`, затем `pip install -r prototype/requirements.txt` и `python -m uvicorn server:app --app-dir prototype --host 127.0.0.1 --port 8000`.

Нажмите **Загрузить DEV**, выберите диалог и создайте оценку. Без ключа работает `CQA_PROVIDER=mock`. Кнопка **MOCK: проверить механизм** создаёт пустой черновик через адаптер провайдера и записывает трассу вызова. Она **не выставляет оценки**. Чтобы получить осмысленный итог без API-ключа, заполните вручную все критерии: применимость, evidence, официальную ступень и объяснение. Итог появится только после прохождения проверки.

## Этапы

1. Исходные роли, язык, timestamps и текст хранятся в SQLite; реплики нумеруются. Кнопка «Показать точный запрос к модели» показывает нормализованный вход и полный чек-лист. В mock-режиме ответ содержит `sent: false`.
2. У каждого критерия отдельно редактируются применимость и причина N/A. Если N/A запрещён, его нет в интерфейсе и отклоняет проверка.
3. Номера evidence можно добавить кликом по репликам или вручную. Цитата берётся из сохранённого transcript, а не из текста модели. Для пропущенного действия укажите проверенный участок.
4. Ответ выбирается только из официальных ступеней. Объяснение обязательно.
5. Пока решение неполное или содержит ошибки, итог не показывается. Ошибки видны по критериям.
6. Python пересчитывает баллы, эффективный вес после N/A, секции и отдельный флаг грубых ошибок. Модель не считает итог.
7. Апелляция фиксирует исходное решение и исходный итог. Проверяющий подтверждает или меняет поля и пишет причину; итог пересчитывается. Открытый спорный критерий нельзя изменить в обход решения.
8. Журнал хранит изменения, версии, полный ответ модели, использование токенов, длительность и стоимость, если известны цены токенов. Сравнение с последним проходом показывает изменённые критерии.

Один AI-вызов возвращает применимость, evidence и оценки для всех критериев. Этапы 2–4 видимы и редактируемы после вызова; независимых вызовов на каждом этапе сейчас нет. После ручной правки проверка и расчёт выполняются повторно по исправленным данным.

## Подключение реальной модели

Заполните `.env` в корне репозитория и перезапустите сервер:

```dotenv
CQA_PROVIDER=openai
CQA_LLM_MODEL=<доступная-модель>
CQA_LLM_API_KEY=<локальный-ключ>
```

`openai` использует Chat Completions; `CQA_LLM_URL` позволяет указать совместимый endpoint. `gemini` использует поддерживаемый REST `generateContent`; для него задайте `CQA_PROVIDER=gemini`, модель и ключ. Реальные модели не были вызваны без ключа. Доступность, стоимость и точность конкретной модели нужно проверить после подключения. Если известна цена на миллион входных и выходных токенов, задайте `CQA_INPUT_USD_PER_MILLION` и `CQA_OUTPUT_USD_PER_MILLION`; иначе стоимость честно остаётся неизвестной.

Документация API: [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [Gemini generateContent](https://ai.google.dev/api/generate-content).

## Данные, версии и сравнение

- Файлы JSON можно загрузить через интерфейс: одну запись, массив записей или исходный ответ API организаторов.
- Для нового `group_id` заполните `CQA_API_URL` в `.env`, затем используйте кнопку загрузки. Подписанный URL не сохраняется в Git.
- Пакетный прогон обрабатывает диалоги, видимые после фильтрации списка. Результаты каждой записи сохраняются отдельно. Статус текущего пакетного задания хранится в памяти процесса; после перезапуска результаты остаются в SQLite.
- Редактор чек-листа публикует новую неизменяемую версию. Для отдельного чек-листа измените ID. Новые оценки могут выбрать любой опубликованный ID и версию. Старые оценки хранят собственный снимок правил.
- База по умолчанию: `prototype/state.db` (игнорируется Git). Можно изменить через `CQA_PROTOTYPE_DB`.
- Запись звонка открывается ссылкой на плеер организаторов. Переход по evidence выделяет реплику transcript; автоматическая перемотка аудио пока не реализована.

После ручной разметки DEV командой, файл меток в формате JSON можно передать в `prototype/compare.py`:

```json
[{"conversation_id":"p1-ru-001","answers":{"c01":{"applicability":"applicable","answer":"yes","na_reason":"","evidence_idx":[10],"explanation":"..."}}}]
```

Нужны **все** критерии каждого размеченного диалога. Команда `python prototype/compare.py labels.json` считает совпадение ответов, N/A precision/recall, точные ступени, MAE итогового балла и пересечение evidence. Сравнивается сохранённый **исходный ответ реальной модели до ручных правок**. Mock и ручные оценки исключаются. Ручные метки команды не являются скрытым Ground Truth организаторов.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pip install -r prototype\requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s prototype\tests -v
node --check prototype\web\app.js
```

Тесты проверяют официальный чек-лист, N/A, точные ступени, отдельный флаг, пустой знаменатель, версии, импорт 65 DEV, ручное решение, апелляцию и пакетный mock-прогон.

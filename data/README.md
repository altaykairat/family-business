# Данные

| Путь | Что это |
|---|---|
| `checklists/default.json` | Начальный чек-лист из PDF (8 критериев) в машиночитаемом виде — конфигурация по умолчанию |
| `dev/raw.json` | Исходный ответ API организаторов для `group_id=DEV` (без изменений, отформатирован) |
| `dev/index.md`, `dev/index.csv` | Список диалогов: канал, язык, число реплик, последнее системное событие |
| `dev/conversations/<id>.json` | Запись диалога; к каждой реплике добавлен порядковый номер `idx` (с 1) для ссылок-доказательств |
| `dev/transcripts/<id>.md` | Читаемый транскрипт в виде таблицы; у звонков время — смещение от начала |

## Набор DEV

65 диалогов: 60 синтетических чатов (30 RU, 15 KZ, 15 EN) и 5 реальных звонков (RU). Роли: `client`, `operator`, `bot`, `system`. Время у чатов `MM:SS`, у звонков ISO 8601.

Каждый чат устроен одинаково: вопрос клиента → бот AIM → эскалация на оператора (`system`) → работа оператора → иногда системное событие о завершении («Оператор закрыл чат», «Соединение с клиентом прервано», «Клиент покинул чат»).

## Обновление и контрольный набор

```bash
cp .env.example .env   # вписать CQA_API_URL из docs/task.md
python3 scripts/fetch_dataset.py DEV
python3 scripts/fetch_dataset.py <CONTROL_GROUP_ID>   # в +23 ч, сохранит в data/<group_id>/
```

Скрипт использует только стандартную библиотеку Python 3.9+.

## Записи звонков

`audio_url` ведёт не на аудиофайл, а на HTML-страницу плеера. Внутри неё — тег `<audio>` со ссылкой на mp3 в Dynamics 365 (`.../api/filedownload/...`), подписанной примерно на 1 час. Поэтому mp3 не сохраняется в репозитории: для прослушивания и перемотки к реплике сервер должен каждый раз открывать страницу плеера и брать из неё свежую ссылку на mp3.
